## Implementation and integration findings

### DG-08 - GitHub workflow bootstrap scope

The existing DG-08 proposal covers the reusable drift workflow. Two other workflows at the implementation snapshot have the same checkout dependency. `templates/github-workflows/specs.yml:64-67,102-126` and `templates/github-workflows/text-integrity.yml:69-77,92-116`. Both use recursive submodule checkout and then run `.devgate` scripts. The latter also dispatches `.devgate/tests/` controls and preserves a full-history range scan. `spec-coherence.yml` has a separate existing bootstrap; bundle-size and file-size templates mention `.devgate` in comments but do not invoke it at runtime. The DG-08 package now covers all three affected workflows. Its contract has been expanded with hermetic acceptance for each entry point. Implementation tasks remain open.

### DG-17 - checksum inventory loses quoted Unicode paths

At `scripts/gen-checksums.py:26-34`, `git ls-files` output is read as newline-delimited text and extension-filtered. A disposable repository with `core.quotePath=true`, `scripts/ordinary.py`, and `scripts/r\u00e9sum\u00e9.py` reproduced false success against `ac61e20`: generation wrote one checksum and verification exited 0 with one checksum. DG-16's malformed/duplicate record checks do not cover inventory omission. The separate DG-17 proposal requires NUL-delimited path parsing, strict path representability checks, shared generator/verifier failure, and no partial manifest acceptance. The follow-up implementation and cross-platform verification are recorded in [DG-17 evidence](../changes/dg17-checksum-unicode-path-inventory/evidence.md).

### DG-18 - YAML source marker omitted by shared traceability discovery

`scripts/lib/spec_discovery.py` does not include `.yml` or `.yaml` in `SCAN_EXTS`; consequently `scripts/spec_traceability.py --report` lists `glf-template-bootstrap-01` as uncovered even though its actual marker is at `templates/gitlab-ci/includes/devgate-bootstrap.yml:1`. Existing stable-ID work (`spec-fmt-04/05`) does not define YAML source eligibility or exclusion controls. The separate DG-18 proposal narrows YAML scanning to owned CI source directories and requires fixture/example exclusions plus scalar-text controls. No scanner implementation or coverage credit is claimed here.
