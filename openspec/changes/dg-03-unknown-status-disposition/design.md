# Design

## Context

See proposal.md. Current UNKNOWN capabilities are adapters-and-loops, art-creation-contract, branch-drift, evidence-claims, fleet-app-enrollment, open-item-aging, reviewer-surfaces, secret-rotation, spec-state-ledger, surface-reach, traceability-and-drift, and tree-clean. Three have no supported IDs due to missing heading markers; that format issue is handled separately by DG-01.

## Goals / Non-Goals

**Goals:** distinguish documented intent and available evidence without converting documentation into proof.

**Non-Goals:** force all specs to CLOSED, duplicate the state ledger, or reinterpret the existing game-matrix DEFERRED decision.

## Decisions

- Use a disposition record with capability, requirement ID (or missing-ID heading reference), owner, evidence pointer, evidence date, and outcome `verified`, `insufficient`, `external-owner`, or `not-reviewed`. These labels describe audit disposition, not lifecycle state.
- Keep lifecycle status generated by current closure/ledger rules. A disposition of verified requires a link to existing evidence but does not create terminal status absent the required ledger row.
- Require an explicit reason and responsible owner for `external-owner` and `not-reviewed`; avoid silent defaults.
- Exclude `game-type-phase-matrix`, whose existing owner answer is DEFERRED, while retaining it in the audit index.

## Risks / Trade-offs

- [Disposition might be mistaken for closure] -> label it as an audit annotation and render the lifecycle status separately.
- [Owner identity may be unknown] -> mark `not-reviewed` with owner `unassigned`, not an inferred person.

## Migration Plan

Create a baseline inventory for all 12 UNKNOWN specs, review each requirement and evidence path, assign owner/status with provenance, then regenerate INDEX without changing lifecycle state.
