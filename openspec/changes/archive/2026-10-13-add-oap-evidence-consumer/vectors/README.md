# OAP evidence v2 reference vectors

`oap-evidence-v2-vectors.json` freezes the canonical-byte / signature /
verdict facts a second, cross-language implementation of the
`devgate.oap-evidence/v2` receiver must reproduce **exactly**.

## Status — read this first

- These are **Python-produced reference vectors**. They are generated by the
  existing Python code path
  (`hub/coherence/oap_v2_producer.produce` → `hub/coherence/strict_parse` →
  `hub/coherence.oap_observer`), test fixtures are in
  `tests/fixtures/oap/oap_vectors.py`.
- **No Go OAP receiver exists in this repository.** An independent Go
  implementation lives in the sibling `openagentplatform` repo
  (`cmd/oap-observer`, branch `feat/oap-evidence-v2-receiver`).
- **Consumption of these vectors by the Go implementation is now `EXERCISED`**
  for the frozen set: the independent Go observer read this exact file
  (byte-identical, SHA-256 pinned) and reproduced the expected verdict for all
  13 cases — 1 positive + every Gate 1-2 negative. See
  `PARITY-go-oap-observer.md`, `PARITY-COMMANDS.txt`, and
  `PARITY-OBSERVER-OUTPUT.jsonl`. This proves a receiver read and agreed with
  them over a real process/language boundary; it is still observe-only and
  non-authorizing, and does NOT exercise deployed transport or independent
  review.
- Everything is **NON-AUTHORIZING / observe-only**. A passing vector is a
  mathematical + binding verdict over fixed bytes. It is **not** authenticity,
  **not** authorization, and grants **no** OAP effect.

## Contents

Each entry under `cases` carries the presented wire artifact
(`canonical_bytes_hex`), the receiver-recomputed signed bytes
(`signed_bytes_hex`), the signing public key and key id, the signature, the
reference time / audience / trust store name, and the `expected` verdict
(`ok` + `reason`, or a `sequence` for the replay case).

The cases cover one valid artifact plus the adversarial set:

| case | category |
|------|----------|
| `valid_artifact` | valid |
| `identity_low_order_key_forgery` | forgery |
| `wrong_domain_separation_tag` | forgery |
| `duplicate_json_key` | structural |
| `expired_timestamp`, `not_yet_valid_timestamp`, `key_out_of_window` | window |
| `wrong_audience`, `key_audience_mismatch`, `wrong_tenant` | context |
| `lying_digest`, `lying_cross_link` | binding |
| `replayed_jti` | replay |

## Regenerating and pinning

- Regenerate: `python tests/fixtures/oap/oap_vectors.py` (rewrites the file in
  place; byte-identical on any host while the code is unchanged).
- `tests/test_oap_evidence_vectors.py` **regenerates from the current code and
  asserts byte-identity** to the committed file, plus a SHA-256 pin, so any
  silent drift in the producer / parser / trust store / observer fails CI.
  The test never overwrites the committed file; drift must be an explicit,
  reviewed regeneration.
