# Spec: Art creation contract

## ADDED Requirements

### Requirement: one definition of done

<!-- id: art-done-01 -->

An art asset SHALL be considered done only when it is visible in a shipped
build on **every** target platform the title ships, and its provenance record
is complete. Completion SHALL NOT be established by a file existing, by a
counter incrementing, by a stage logging success, or by a manifest being
rewritten.

A stage that produces output with no consumer SHALL NOT contribute to done.

#### Scenario: file written is not done

- **GIVEN** a packed game mesh exists on disk and no shipped build loads it
- **WHEN** the asset's stage is evaluated
- **THEN** it is not done, and the missing consumer is reported as the blocker.

#### Scenario: a counter is not done

- **GIVEN** a library counter has incremented for an asset
- **WHEN** that asset has no rendered frame on one of the shipped targets
- **THEN** the asset is not done and the quantity gate is not green.

### Requirement: art brief before generation

<!-- id: art-brief-01 -->

Generation of art assets SHALL be refused unless a versioned art brief exists
and is referenced by the asset. The brief SHALL contain a readability brief, art
direction pillars, a palette and value structure, a shape language, a footprint
or scale grid, material families, and a camera or lens statement.

#### Scenario: generation with no brief

- **GIVEN** no art brief is present, or no brief reference is recorded
- **WHEN** an art generation run is requested
- **THEN** the run is refused and no asset record is created.

### Requirement: shape language names a rule per class

<!-- id: art-brief-02 -->

The brief's shape language SHALL name, per asset class, the geometric rule an
asset of that class must satisfy. Acceptance of a concept SHALL reference the
rule it was checked against.

#### Scenario: a concept outside its class rule

- **GIVEN** a brief whose furniture class requires orthogonal, rectilinear
  silhouettes
- **WHEN** a generated concept for a bed presents an oval plan silhouette
- **THEN** the fidelity gate fails the asset and it does not advance, whatever
  its automated scores.

#### Scenario: acceptance with no rule named

- **GIVEN** a fidelity verdict that does not name a class rule
- **WHEN** the asset is proposed to advance
- **THEN** advancement is refused; a verdict without a rule is not a verdict.

### Requirement: every stage names its consumer

<!-- id: art-stage-01 -->

Every declared pipeline stage SHALL state its input, its output, **the code
that reads that output**, and its determinism requirement. A stage whose
consumer is absent, or named as none, SHALL fail the contract check.

A documented terminal artifact with no consumer SHALL be reported as a contract
violation, not as an incomplete stage.

#### Scenario: terminal artifact with no reader

- **GIVEN** a pipeline document names `assets/<id>/mesh` as its terminal output
- **WHEN** no code in the title reads that path or format
- **THEN** the contract check fails and names the stage and the missing consumer.

#### Scenario: consumer path does not exist

- **GIVEN** a stage names a consumer by path
- **WHEN** that path is absent from the title's tree
- **THEN** the contract check fails on that stage.

### Requirement: provenance ledger is the inventory

<!-- id: art-ledger-01 -->

The inventory of a title's art SHALL be a machine-readable ledger with one row
per asset, carrying at minimum: asset id, asset class, current stage, brief
reference, prompt, seed, content digests for every stage artifact, per-stage
completion flags, rights classification, and review verdict.

Counts reported in any document SHALL be derived from the ledger. A count that
cannot be derived SHALL be treated as unsourced and SHALL NOT be published.

#### Scenario: asset outside the ledger

- **GIVEN** an artifact exists under an art output directory
- **WHEN** no ledger row identifies it
- **THEN** the contract check fails and names the artifact.

#### Scenario: a published count disagrees with the ledger

- **GIVEN** a status document prints a library count
- **WHEN** that number does not match the ledger-derived count
- **THEN** the document-truth check fails; see `doc-truth`.

### Requirement: bytes are versioned and replicated

<!-- id: art-bytes-01 -->

Generated art bytes SHALL live in a canonical store that is versioned, and
SHALL have at least one additional copy. The restore path from the additional
copy SHALL have been exercised and recorded.

Omitting generated bytes from a code repository is permitted only when ledger
digests make them reproducible and the restore has been tested. Cleanup of art
bytes SHALL be a recorded deletion with a reason; it SHALL NOT be a side effect
of storage pressure.

#### Scenario: cleanup deletes the only copy

- **GIVEN** prepared art exists only on one working host
- **WHEN** a storage cleanup removes it
- **THEN** the ledger shows the digests as unrestored and the asset is not done;
  the loss is detectable without a human noticing a visual defect.

#### Scenario: restore has never been run

- **GIVEN** an additional copy exists
- **WHEN** no recorded exercise of the restore path exists
- **THEN** the contract check fails on replication.

### Requirement: fidelity gate

<!-- id: art-accept-01 -->

Every asset SHALL carry a recorded human fidelity verdict against its brief
before it advances. The verdict SHALL state which class rule or character
diagram the asset was checked against and whether it satisfied it.

An automated score SHALL NOT substitute for the fidelity verdict.

#### Scenario: automated score without a verdict

- **GIVEN** an asset with measured scores and no fidelity verdict
- **WHEN** the asset is proposed to advance
- **THEN** advancement is refused and the missing verdict is the blocker.

#### Scenario: perfect retention on the wrong shape

- **GIVEN** an asset whose source silhouette is the wrong shape for its class
- **WHEN** retention is measured at the maximum
- **THEN** the asset still fails, because retention answers a different question
  than fidelity.

### Requirement: retention measured beside the verdict

<!-- id: art-accept-02 -->

Pipeline retention or quality measurements SHALL be recorded alongside the
fidelity verdict and SHALL NOT be reported as the verdict. A measurement with
no stated threshold or no stated meaning SHALL be labelled as such and SHALL NOT
be used as a gate.

#### Scenario: a measurement with no threshold

- **GIVEN** a retention measurement whose scale has no defined pass threshold
- **WHEN** it is reported
- **THEN** it is labelled as a measurement only and no pass or fail is derived
  from it.

### Requirement: every target must draw

<!-- id: art-draw-01 -->

Every target platform a title ships SHALL produce a rendered-frame capture
from the title's own renderer, checked in CI. A capture that contains no game
geometry SHALL fail the check.

A preview rendered by a content-creation tool SHALL NOT satisfy this
requirement. A target whose render loop only clears buffers SHALL be reported
as a failing target, not as a passing one.

#### Scenario: a platform that clears a buffer

- **GIVEN** a shipped web target whose frame routine clears a color buffer and
  submits no draw calls
- **WHEN** the target-draws check runs
- **THEN** it fails and names the target; the build is not shippable on that
  target.

#### Scenario: a DCC preview offered as evidence

- **GIVEN** a Blender or similar preview image offered as render evidence
- **WHEN** the target-draws check runs
- **THEN** it is rejected; only the game's own renderer on a shipped target
  satisfies the requirement.

### Requirement: rights recorded at generation

<!-- id: art-rights-01 -->

Rights classification SHALL be recorded on the asset's ledger row at generation
time. The value `unknown` SHALL be a recorded value, not an absence.

Unknown rights SHALL block the public build and SHALL NOT block creative or
gray-box work. See `publish-safety` for the publish-time enforcement.

#### Scenario: blank rights field

- **GIVEN** a ledger row whose rights field is empty
- **WHEN** the ledger is validated
- **THEN** the row is invalid; `unknown` must be written explicitly.

### Requirement: quantity gates run last

<!-- id: art-qty-01 -->

Library floors, piece counts and coverage percentages are floors. A quantity
gate SHALL NOT report green while any asset is failing the fidelity gate.

Shortfall and fidelity failure SHALL be reported as separate quantities and
SHALL NOT be collapsed into a single number.

#### Scenario: floor met, fidelity failing

- **GIVEN** the asset count meets the declared floor
- **WHEN** one or more assets are failing the fidelity gate
- **THEN** the quantity gate is not green and both conditions are printed.

#### Scenario: floor not met, every verdict green

- **GIVEN** a declared library floor of five and one accepted asset
- **WHEN** the quantity gate runs
- **THEN** it fails on the shortfall alone, printing floor, counted and
  shortfall, even though no fidelity verdict is failing.

### Requirement: the contract grows from the failure registry

<!-- id: art-evolve-01 -->

Each art failure class that reaches a human SHALL be appended to the failure
registry with a prevention rule. Where a class is not covered by an existing
requirement of this contract, the contract SHALL be extended to cover it.

The registry entry's prevention rule SHALL name the requirement that would have
prevented the class, or SHALL propose a new one.

#### Scenario: a new failure class appears

- **GIVEN** a failure class not covered by any existing requirement here
- **WHEN** it is logged to the failure registry
- **THEN** a contract extension is required, and the registry entry names the
  gap until it lands.

#### Scenario: a class already covered

- **GIVEN** a failure class that an existing requirement already prevents
- **WHEN** it is logged
- **THEN** the prevention rule cites that requirement and no contract change is
  required.
